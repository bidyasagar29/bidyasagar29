# Deployment & automation

The profile cards are regenerated by `.github/workflows/update-profile.yml` every
day at `03:00 UTC`, and on demand from the **Actions** tab.

## Required secrets

| Name | Where it comes from | Required |
| --- | --- | --- |
| `GITHUB_TOKEN` | Automatically issued by GitHub Actions for every run | Yes (automatic) |
| `GH_TOKEN` | Optional personal access token for local runs only | No |

No repository secret has to be created. The workflow reads the automatically
issued `GITHUB_TOKEN`, which is used for the GitHub REST/GraphQL requests and
expires when the job ends. Never commit a token to this repository.

For local runs, create a fine-grained or classic personal access token with
read access to public repositories and set it as `GH_TOKEN` (or
`GITHUB_TOKEN`) in your shell. The public contribution calendar also works
without a token, but a token avoids API rate limits.

## Required permissions

The workflow declares:

```yaml
permissions:
  contents: write
```

`contents: write` lets the job push regenerated cards and data. If pushes are
rejected, open **Settings → Actions → General → Workflow permissions** and
enable **Read and write permissions** for the repository.

## First-time setup

1. Push this repository to GitHub with the default branch named `main`.
2. Open **Settings → Actions → General**.
3. Under **Workflow permissions**, select **Read and write permissions** and
   save.
4. Open the **Actions** tab, select **Update profile cards**, and run it once
   with **Run workflow**. This verifies the token, dependencies, and commit
   permissions.
5. Confirm that `cards/`, `data/github_stats.json`, and
   `data/contributions.json` were committed by `github-actions[bot]`.
6. The daily schedule starts automatically; no additional secret is needed.

The repository must be named exactly like the GitHub username
(`bidyasagar29/bidyasagar29`) for the README to appear on the profile page.
The profile README repository itself is excluded from the featured cards.

## Manual runs and previews

```powershell
pip install -r requirements.txt

# Animated cards used by the README (requires network for fresh stats)
python generate_cards.py

# Final-frame cards for local screenshots (no animation CSS)
$env:STATIC = "1"
python generate_cards.py --out preview
Remove-Item Env:\STATIC

# Render from cached data when offline
python generate_cards.py --offline
```

`STATIC=1` (or `--static`) removes all `@keyframes`/`animation` rules and
renders the final frame. Normal mode keeps the staggered animations and the
`prefers-reduced-motion` fallback.

## Commit behaviour and loop prevention

The commit step stages only generated output:

```text
cards/
data/github_stats.json
data/contributions.json
```

`data/profile.json` is configuration, not generated data, so it is never
committed by the bot. The workflow triggers only on changes to
`generate_cards.py`, `data/profile.json`, `requirements.txt`, or the workflow
file, and ignores pushes that touch only generated output. Commits also use the
`[skip ci]` marker. Together these prevent bot commits from re-triggering the
workflow.

## Data integrity

- Stars, forks, followers, repositories, and account age come from the GitHub
  API.
- Contributions come from the public contribution calendar (or GraphQL when a
  token is available) for the rolling 12-month window.
- Missing repository descriptions use a curated description from
  `data/profile.json`; no project functionality is invented.
- The workflow aborts if any SVG is malformed, a README image path is missing,
  or the contribution data is invalid.
